# PrimeCare Reporting Module

## Overview
The reporting module provides comprehensive management reporting capabilities for the PrimeCare clinic application. It includes interactive dashboards, detailed reports, and multiple export formats.

## Features

### 1. **Management Dashboard**
   - Overview of clinic operations
   - Key performance indicators (KPIs)
   - Real-time statistics
   - Visual charts and graphs

### 2. **Report Categories**

#### **Overview Report**
   - Total doctors, patients, and specialities
   - Appointment statistics (total, confirmed, completed, cancelled)
   - Revenue metrics (total and monthly)
   - Top specialities by appointment volume
   - Recent appointments list

#### **Appointments Report**
   - Filterable by date range, status, doctor, patient, or speciality
   - Summary statistics
   - Detailed appointment list with all information
   - Export capabilities

#### **Doctors Report**
   - Performance metrics for each doctor
   - Appointment counts (completed, upcoming, cancelled)
   - Revenue generated per doctor
   - Consultation fee information
   - Average statistics across all doctors

#### **Revenue Report**
   - Total revenue calculation
   - Revenue trends over time (daily, weekly, or monthly)
   - Revenue breakdown by speciality
   - Average revenue per appointment
   - Date range filtering

#### **Specialities Report**
   - Doctor count per speciality
   - Appointment volume per speciality
   - Revenue generated by speciality
   - Average consultation fees
   - Completion rates

#### **Patients Report**
   - Total and active patient counts
   - Gender distribution
   - Patient visit history
   - Age demographics
   - Last visit dates

### 3. **Export Formats**
The reports can be exported in multiple formats:

- **CSV**: Comma-separated values for spreadsheet applications
- **Excel (.xlsx)**: Formatted Excel workbooks with styling
- **JSON**: Structured data for programmatic access
- **Print**: Print-friendly page layout

### 4. **Visualizations**
   - Bar charts for speciality comparisons
   - Line charts for revenue trends
   - Pie/Doughnut charts for distributions
   - Responsive and interactive charts using Chart.js

## API Endpoints

### Report Data Endpoints

#### Get Summary Report
```http
GET /reports/summary
```
Returns overall clinic statistics and KPIs.

#### Get Appointments Report
```http
GET /reports/appointments?start_date=YYYY-MM-DD&end_date=YYYY-MM-DD&status=STATUS
```
**Query Parameters:**
- `start_date` (optional): Filter appointments from this date
- `end_date` (optional): Filter appointments to this date
- `doctor_id` (optional): Filter by specific doctor
- `patient_id` (optional): Filter by specific patient
- `status` (optional): Filter by status (confirmed, completed, cancelled, no_show)
- `speciality_id` (optional): Filter by speciality

#### Get Doctors Report
```http
GET /reports/doctors
```
Returns performance statistics for all active doctors.

#### Get Specialities Report
```http
GET /reports/specialities
```
Returns performance metrics for all specialities.

#### Get Patients Report
```http
GET /reports/patients
```
Returns patient statistics including demographics and visit history.

#### Get Revenue Report
```http
GET /reports/revenue?start_date=YYYY-MM-DD&end_date=YYYY-MM-DD&group_by=month
```
**Query Parameters:**
- `start_date` (optional): Filter revenue from this date
- `end_date` (optional): Filter revenue to this date
- `group_by` (optional): Grouping period (day, week, month) - default: month

### Export Endpoints

#### Export Report
```http
GET /reports/export/{report_type}?format=FORMAT&[filters]
```
**Path Parameters:**
- `report_type`: Type of report (appointments, doctors, revenue)

**Query Parameters:**
- `format`: Export format (csv, excel, json)
- Additional filters based on report type (same as data endpoints)

**Example:**
```http
GET /reports/export/appointments?format=excel&start_date=2026-01-01&end_date=2026-12-31
```

## Usage

### Accessing Reports
1. Navigate to the Reports page from the main navigation menu
2. Select the desired report tab
3. Apply filters if needed
4. View the interactive report with charts and tables

### Filtering Reports
1. Use the filter panel at the top of each report
2. Select date ranges, statuses, or other criteria
3. Click "Apply Filters" to refresh the report
4. Click "Clear" to reset filters

### Exporting Reports
1. Navigate to the desired report tab
2. Apply any filters you want
3. Click one of the export buttons:
   - **Export CSV**: Download as comma-separated values
   - **Export Excel**: Download as formatted Excel workbook
   - **Export JSON**: Download as JSON data file
4. The file will be downloaded to your browser's download folder

### Printing Reports
1. Navigate to the desired report
2. Use your browser's print function (Ctrl+P or Cmd+P)
3. The page will automatically format for printing
4. Navigation and filter panels are hidden in print view

## Technical Details

### Backend Implementation
- **Language**: Python 3.x
- **Framework**: Flask
- **Database**: PostgreSQL
- **Libraries**:
  - `psycopg2`: Database connectivity
  - `openpyxl`: Excel file generation
  - `flask-cors`: CORS support

### Frontend Implementation
- **Template Engine**: Jinja2
- **Charting Library**: Chart.js 4.4.0
- **Styling**: Custom CSS with theme support (light/dark)
- **Responsive**: Mobile-friendly design

### Database Queries
All reports use optimized SQL queries with:
- Proper JOINs for related data
- Aggregation functions (COUNT, SUM, AVG)
- Grouping and filtering
- Date range filtering
- Status-based filtering

## Installation

### 1. Install Dependencies
```bash
# API dependencies
cd python/primecare/api
pip install -r requirements.txt

# Web app dependencies
cd ../web-app
pip install -r requirements.txt
```

### 2. Start the API Server
```bash
cd python/primecare/api
python app.py
```
The API will run on `http://localhost:5000`

### 3. Start the Web Application
```bash
cd python/primecare/web-app
python client.py
```
The web app will run on `http://localhost:5001`

### 4. Access Reports
Open your browser and navigate to:
```
http://localhost:5001/reports
```

## Configuration

### API URL
The reports page connects to the API at `http://localhost:5000` by default. To change this:

1. Edit `reports.html`
2. Update the `API_BASE` constant:
```javascript
const API_BASE = 'http://your-api-url:port';
```

### Database Connection
Configure database connection in `api/app.py`:
```python
DB = dict(
    host=os.getenv('DB_HOST', 'localhost'),
    port=int(os.getenv('DB_PORT', '5432')),
    dbname=os.getenv('DB_NAME', 'clinic'),
    user=os.getenv('DB_USER', 'postgres'),
    password=os.getenv('DB_PASSWORD', ''),
)
```

Or set environment variables:
```bash
export DB_HOST=localhost
export DB_PORT=5432
export DB_NAME=clinic
export DB_USER=postgres
export DB_PASSWORD=yourpassword
```

## Performance Considerations

1. **Caching**: Consider implementing caching for frequently accessed reports
2. **Pagination**: For large datasets, implement pagination in the API
3. **Indexes**: Ensure proper database indexes on frequently queried columns
4. **Query Optimization**: Use EXPLAIN ANALYZE to optimize slow queries

## Security Considerations

1. **Authentication**: Add authentication middleware to protect report endpoints
2. **Authorization**: Implement role-based access control for sensitive reports
3. **Input Validation**: All query parameters are validated and sanitized
4. **SQL Injection**: Using parameterized queries to prevent SQL injection
5. **Rate Limiting**: Consider adding rate limiting for export endpoints

## Troubleshooting

### Reports Not Loading
- Check that the API server is running
- Verify the API_BASE URL is correct
- Check browser console for JavaScript errors
- Ensure database connection is working

### Export Fails
- Verify openpyxl is installed for Excel exports
- Check file permissions in the download directory
- Ensure the API endpoint is accessible

### Charts Not Displaying
- Verify Chart.js library is loading
- Check browser console for errors
- Ensure data is being returned from API

### Slow Performance
- Check database indexes
- Optimize SQL queries
- Consider implementing caching
- Reduce date range for large datasets
